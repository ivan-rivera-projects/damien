## 2. The queue, in order

### 1. The `label:` → `category:` translation in `rules.to_query` *(quick: one commit with a test)*

**Why:** a rule that says `label contains CATEGORY_PROMOTIONS` compiles to `label:category_promotions`,
which matches **0** messages — Gmail needs `category:promotions`. Verified live: `label:category_promotions`
→ 0, `category:promotions older_than:365d` → **286**, `category:social older_than:182d` → 1. So the two
**seed** rules `r-old-promotions` and `r-old-social` have never fired, in any install. This is not a
regression from `v0.4.0` — the old uppercase form returned 0 as well.

**The fix:** in `rules.to_query`, translate a `label` condition naming a `CATEGORY_*` value into
`category:<lowercased-suffix>`. Acceptance: both seed rules emit a `category:` query and match >0 on a real
mailbox; a test pins the translation. Note the guardrail below holds such mail back from being filed anyway,
so this is correctness, not a behaviour change.

## 3. The roadmap: weeks of use → IMAP → announce

It stays public and MIT in the meantime; discovery is welcome and nothing needs promoting.

**The one caveat to carry into the IMAP phase — it changes the pitch, not just the code.** "Rules are free"
comes from Gmail evaluating a rule **server-side as a query**: no headers fetched, no model, no cost.
IMAP has no equivalent, so rules would run locally over fetched headers — **free becomes cheap but not
free** — and the cost section, the SETUP guidance and the "a settled mailbox costs $0" claim all need
re-scoping for that provider rather than reusing Gmail's numbers.

The migration itself is mostly `gmail.py`'s surface (list, fetch, label/move). The decision engine, the
store, the plan/apply/journal machinery and the rules stay as they are, with 300 tests behind them.

**PyPI is now a channel, not a held-back item** — `v0.4.1` publishes itself from a tag. Worth naming plainly:
that is a *more* discoverable act than the repo ever was, so the tool can be found and installed by a stranger
today. Everything they need is in place for that (`doctor` names each missing step, SETUP walks the OAuth
client, PRIVACY states exactly what leaves the machine, MIT), which is why it is a fair thing to have done
before the announcement — but it is worth knowing that the "announcement" is no longer the first moment anyone
could find it.

Deliberately held back, none started: IMAP, more than one account per install, one-click unsubscribe.

## 4. How to work here (the traps that cost this session the most time)

- **One working tree, two actors.** The live checkout is what the scheduled pass runs from, and another
  agent may be editing it mid-flight. Check `git status` before touching anything and never assume the tree
  is yours.
- **Name the window on every plan build.** An unscoped `-q 'in:inbox'` rebuilt the whole mailbox: 4,287
  judgements, **$0.26**, where the scoped rebuild of the window I actually wanted was **free** because the
  cache was warm.
- **The verdict cache key is (model + judge host + the questions as written + the message state, body
  included).** Any change to the buckets, the profile, the model or the judge host re-judges everything
  once — $0.07–0.26 on this mailbox. A **rule** change is free.
- **`label:` is not `category:`**, and the two matchers differ: `from:domain.com` in a Gmail *query* does
  not match subdomains, but `contains "domain.com"` in the **local** matcher does — and `plan build` uses
  the local one, first match wins. That is how a broad minted rule can silently kill a narrower one.
  `damien rules list` marks shadowed rules in yellow; run it after any rule change.
- **Ids and notes do not belong in one shell field.** A loop over `id:note` pairs split on the spaces in
  the notes and wrote twelve junk corrections for ids like `sale` and `ship`. They were found by querying
  for corrections whose message does not exist; keep the two apart.
- **Version metadata and the source tree can disagree.** An editable install runs the tree while reporting
  the metadata of whenever it was installed. `damien version` now prints both and `doctor` warns; the fix
  it names is `uv tool install --editable '.[pg,vectors]' --force`.
- **A skill or schedule that names a deleted file breaks silently.** When the *interface* moves, the agent
  skill and the cron prompts need updating — which is why the pass report now *prints* the closing step
  (`rules from-senders <plan_id>`), so a thin skill need only relay it.
- **The layout moved mid-session.** The CLI became a package (`src/damien/cli/*`) for the PyPI release, so
  anything that used to say `cli.py` now means the module that owns the command. The decision engine, the
  store, the rules and `plan.py` did not move.
- **`str.replace` is silent.** Several edits "applied" without matching their anchor and left the file
  untouched. Assert the match before writing; every edit script afterwards did.
- **Running beat reading, every time.** The bugs worth having were found by executing the thing: a privacy
  claim that was false (the docs said there was no send scope; `gmail.modify` permits sending), a rule's
  `keep_in_inbox` dropped by the executor, a stored body excerpt silently dropped by `ON CONFLICT DO
  UPDATE`, a test defined twice under one name so only one ever ran, and stale version metadata stopping an
  agent's floor check. `docs/AUDIT-BRIEF.md` is the shape that finds these — invariants, the claims to
  verify, and where defects hide.
